# Layout costs: l01

49 layouts: 42 uniform (composed); 7 uniform (measured).

- `query_costs.csv`: per (query, layout, chunk view), the picked plan (`body`) and one run's cost (the mean over the reported params): wops (G + 1.1 S + 0.01 N), bytes, wops_bytes4k (wops + bytes / 4096), every raw channel, and the bill's unit lanes. Two rows per query and layout: the half and the measured chunk view (`chunk_view`, below); a read query's two rows are equal, and the bill is on the measured rows (of a measured source).
- `query_parts.csv`: the same plan's cost per run on each part kind (adj, props, index).
- `layouts.csv`: per (layout, chunk view), the totals at the workload's frequencies: total ops = read wops + the writes' own reads (same weights) + PUTs + DELs; total bytes = bytes read + the bytes the writes read first + bytes written; every raw lane. `measured_as`: measured (its own capture), composed (from the measured diagonals' parts: kvcost compose, or a mix costed from its parts), predicted.
- Chunk view: half charges a write's touch of a family's last chunk at the chunk target / 2; measured charges the bytes the capture found (the bill's view).
- `runs.jsonl`: one line per run (argv, layouts, wall_s per stage).
